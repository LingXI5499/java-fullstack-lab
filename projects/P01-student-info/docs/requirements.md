## 1. 项目目标

给教务管理员提供一个可以维护"专业 → 班级 → 学生"三级数据的管理后台：

- 能快速录入与修改学生信息，并立即在校验与错误提示上得到反馈；
- 能按姓名、学号、班级、状态组合筛选并分页浏览，而不是靠肉眼翻长列表；
- 能一眼看到总人数、在读人数、各班级人数分布。

**本项目不解决**：多角色权限、真实登录、批量导入导出、成绩与考勤（分别留给 P06、后续项目）。

## 2. 用户角色与权限边界

| 角色 | 能做什么 | 边界 |
|---|---|---|
| 教务管理员 | 专业/班级/学生的全部增删改查；查看概览统计 | 无跨校数据概念，所有数据属于同一所学校 |
| 只读访客 | 查看学生列表（本项目暂不实现登录，**所有接口当前等价于管理员**） | —— |

> **本项目的认证是显式占位**：所有接口不加认证，`AUTH` 段需求只登记、不实现。
> 真实登录与权限在 P06 引入，届时通过 `change-impact.md` 回填影响面。

## 3. 功能模块

```text
学生信息管理系统
├─ 专业管理  MAJ   增 / 改 / 查 / 停用
├─ 班级管理  CLS   增 / 改 / 查（含所属专业、毕业年份）
├─ 学生管理  STU   增 / 改 / 删 / 查（分页 + 四条件组合）
└─ 概览统计  DASH  总人数 / 在读人数 / 班级分布
```

## 5. 业务规则

规则编号 `BR-<模块>-<序号>`，陈述统一用"**当…且…时，系统必须…**"，每条都能判定真假。

### 5.1 数据校验规则

| 编号 | 规则陈述 | 反面情况 | 可测试性 |
|---|---|---|---|
| STU | 当新增学生时，学号必须全局唯一；重复时系统必须拒绝并返回 `STUDENT_NO_DUPLICATED` | 两个学生共用同一学号，后续成绩无法定位到人 | 连续新增两次相同学号，第二次必须失败 |
| STU | 当录入出生日期时，年龄必须在 15 至 60 周岁之间（按当前日期计算）；越界必须拒绝并返回 `STUDENT_AGE_OUT_OF_RANGE` | 把 200 年出生的人录成学生 | 用 14 岁、15 岁、60 岁、61 岁四个边界验证 |
| STU | 当录入手机号时，若填写则必须为 11 位数字且以 1 开头；不填允许 | 存进 `abc` 或 12 位号码，后续短信功能无法使用 | 用 10 位、11 位、12 位、字母四种输入验证 |
| STU | 当录入姓名时，去除首尾空格后长度必须在 1 至 20 之间 | 存进空格或超长字符串，破坏列表布局 | 提交 0 个字符与 21 个字符验证 |
| CLS | 当新增班级时，同一专业下班级名必须唯一 | 同一专业出现两个"计科1班"，选班时无法区分 | 同专业重复班级名必须失败；不同专业同名必须成功 |
| MAJ | 当新增专业时，专业代码必须唯一且只能包含大写字母与数字，长度 2–10 | 出现两个"CS" | 重复代码与非法字符分别验证 |

### 5.2 状态流转规则

学生状态机：

```text
ENROLLED --休学--> SUSPENDED
SUSPENDED --复学--> ENROLLED
ENROLLED --毕业--> GRADUATED
ENROLLED --退学--> WITHDRAWN
SUSPENDED --退学--> WITHDRAWN
GRADUATED / WITHDRAWN （终态，不可再迁移）
```

| 编号 | 规则陈述 | 反面情况 | 可测试性 |
|---|---|---|---|
| STU | 当学生状态为 `GRADUATED` 或 `WITHDRAWN`（终态）时，系统必须拒绝任何状态变更，并返回 `STUDENT_STATE_INVALID` | 已毕业学生被改回在读，学历数据失真 | 对已毕业学生执行"复学"，必须失败 |
| STU | 当学生状态为 `SUSPENDED` 时，系统必须拒绝直接迁移到 `GRADUATED` | 休学的人直接毕业 | 休学 → 毕业必须失败，休学 → 复学 → 毕业必须成功 |
| STU | 当学生状态不为 `ENROLLED` 时，系统必须在列表中用不同颜色标记该行状态 | 管理员把休学学生当成在读统计 | 前端可见性检查 + 状态字段取值检查 |

### 5.3 关联与删除规则

| 编号 | 规则陈述 | 反面情况 | 可测试性 |
|---|---|---|---|
| STU | 当删除的学生是某班级最后一名学生时，系统必须允许删除，班级本身保留（人数变为 0） | 误删班级及其历史 | 删除后班级仍可查询，人数为 0 |
| CLS | 当删除班级时，若该班级下仍有学生（含任何状态），系统必须拒绝删除并返回 `CLASS_HAS_STUDENTS` | 班级删除后学生成为孤儿数据 | 有学生的班级删除必须失败；清空后必须成功 |
| MAJ | 当停用专业时，若该专业下仍有未停用的班级，系统必须拒绝停用并返回 `MAJOR_HAS_ACTIVE_CLASS` | 停用后班级无法归属专业 | 有活跃班级时停用必须失败 |
| STU | 当把学生转到新班级时，系统必须同时把学生的班级字段更新为新班级 | 学生显示在两个班级里 | 转班后两个班级的人数分别 -1 / +1 |
| STU | 当学生的班级被置空时（本项目不允许），系统必须拒绝 | —— | 本项目前端不提供该操作，接口层需返回参数校验错误 |
| STU | 当新增或修改学生引用的班级不存在时，系统必须拒绝并返回 `CLASS_NOT_FOUND`，不得静默插入 | 学生挂在一个不存在的班级上，成为孤儿数据 | 用 `class_id=999999` 新增学生必须失败 |

### 5.4 查询与分页规则

| 编号 | 规则陈述 | 反面情况 | 可测试性 |
|---|---|---|---|
| STU | 当请求分页时，`page` 必须 ≥ 1，`pageSize` 必须在 1 至 100 之间；越界必须返回参数错误 `PARAM_INVALID`，而不是静默纠正 | 一次拉 10 万条把库拖垮 | 用 `page=0`、`pageSize=0`、`pageSize=101` 验证 |
| STU | 当请求的页码超出总页数时，系统必须返回空列表且 `total` 仍为真实总数，不得报错 | 前端页码错乱导致白屏 | 用超出范围的页码验证 |
| STU | 当按姓名模糊查询时，系统必须对 `%` 与 `_` 做转义，避免用户输入被当作通配符 | 输入 `%` 查出全部数据 | 用 `%` 与 `_` 作为关键词验证 |
| STU | 当未指定排序时，系统必须按 `created_at` 倒序；排序字段只允许白名单（`created_at`、`student_no`、`name`） | 排序参数注入 | 传入非法排序字段必须被忽略或拒绝 |
| STU | 当多个查询条件同时存在时，系统必须把它们组合为 AND 关系，且只拼接非空条件 | 空条件生成 `name LIKE '%%' AND class_id = null` 导致查不到数据 | 只传姓名时，其余条件不得出现在 SQL 中（看日志验证） |

### 5.5 统一契约规则（跨模块）

| 编号 | 规则陈述 | 可测试性 |
|---|---|---|
| COM | 所有接口必须返回 `Result<T>`，其中 `code=0` 表示成功，非 0 表示业务错误 | 任取一个成功与一个失败响应检查结构 |
| COM | 所有可预期的业务失败必须返回业务错误码，HTTP 状态码按语义设置（400/404/409），不得返回 500 | 故意触发 5 类错误，检查响应与 HTTP 状态 |
| COM | 任何日志不得输出密码、完整手机号、完整身份证号；手机号必须脱敏为 `138****8888` | 检查日志文件 |
| COM | 分页响应必须统一为 `PageResult<T>`，包含 `total`、`page`、`pageSize`、`pages`、`list` | 分页接口响应结构检查 |

### 6.1 验收条件写得不可验证的典型症状（自查用）

1. 出现"友好""美观""流畅""合理"这类无法判定的形容词；
2. 只写了条件没写预期输出（"查询学生时应该正确"）；
3. 预期结果是"不报错"——不报错是底线，不是验收条件；
4. 缺少边界值，只有一组正常输入；
5. 没有说明用**什么方式**验证（自动化 / 手工 / 看日志）。

## 8. 数据需求（概念级）

概念实体与关系（物理设计见 `design.md`）：

```text
major (专业) 1 ──── n class (班级) 1 ──── n student (学生)

major : code, name, is_active
class : name, graduation_year, major_id, is_active, student_count(派生)
student: student_no, name, gender, birth_date, class_id, status, phone, remark
```

约定：

- 所有表以 `p01_` 开头，只存在于 `java_fullstack_lab` 单一库中；
- 主键 `bigint unsigned auto_increment`，名为 `<表名后缀>_id`（如 `student_id`）；
- 时间字段 `created_at` / `updated_at`，`datetime`，由应用写入；
- 逻辑删除：本项目**不使用**逻辑删除，删除即物理删除（理由与代价见 `design.md` 的 ADR）；
- **关联一律使用逻辑外键，不建任何物理外键**：`student.class_id` 与 `class.major_id` 都是普通 `bigint unsigned` 列，
  各自建索引（`idx_p01_student_class_id`、`idx_p01_class_major_id`），引用完整性由 Service 层校验；
- 结果就是：**删除班级前必须先查该班级下的学生数量**（`CLS`），**停用专业前必须先查该专业下的活跃班级**（`MAJ`），
  这些校验是业务规则，不是数据库行为，必须有独立用例覆盖。

## 9. 异常与边界

| 场景 | 期望行为 | 错误码 | HTTP |
|---|---|---|---|
| 学生不存在（查询/修改/删除） | 明确提示"学生不存在" | `STUDENT_NOT_FOUND` | 404 |
| 学号重复 | 提示"学号已存在" | `STUDENT_NO_DUPLICATED` | 409 |
| 年龄越界 | 提示"年龄必须在 15–60 之间" | `STUDENT_AGE_OUT_OF_RANGE` | 400 |
| 状态非法迁移 | 提示"当前状态不允许该操作" | `STUDENT_STATE_INVALID` | 409 |
| 班级下有学生仍被删除 | 提示"该班级下仍有学生，无法删除" | `CLASS_HAS_STUDENTS` | 409 |
| 班级不存在 | 提示"班级不存在" | `CLASS_NOT_FOUND` | 404 |
| 同专业班级名重复 | 提示"该专业下已存在同名班级" | `CLASS_NAME_DUPLICATED` | 409 |
| 专业代码重复 | 提示"专业代码已存在" | `MAJOR_CODE_DUPLICATED` | 409 |
| 专业下有活跃班级仍被停用 | 提示"该专业下仍有班级" | `MAJOR_HAS_ACTIVE_CLASS` | 409 |
| 分页参数越界 | 字段级参数错误 | `PARAM_INVALID` | 400 |
| 未捕获的服务端异常 | 返回"系统繁忙，请稍后重试"，日志记录完整堆栈与 traceId | `SYSTEM_ERROR` | 500 |

### 9.1 错误码清单（本项目封闭集合）

**错误码只允许从这张表里取**，新增必须回到本文件登记后再写代码。命名规则：`<领域>_<条件>`，领域用完整单词、
全大写下划线，与该领域的需求编号前缀对应（`STU` 模块的需求，错误码领域段是 `STUDENT`）。

| 错误码 | HTTP | 触发条件 | 对应的异常子类 |
|---|---|---|---|
| `STUDENT_NOT_FOUND` | 404 | 学生 ID 不存在 | `StudentNotFoundException` |
| `STUDENT_NO_DUPLICATED` | 409 | 学号重复 | `StudentNoDuplicatedException` |
| `STUDENT_AGE_OUT_OF_RANGE` | 400 | 年龄不在 15–60 | `StudentAgeOutOfRangeException` |
| `STUDENT_STATE_INVALID` | 409 | 非法状态迁移（含终态保护） | `StudentStateInvalidException` |
| `STUDENT_CONCURRENT_MODIFIED` | 409 | 并发修改同一学生（本项目暂不触发，为 P04 预留） | —— |
| `CLASS_NOT_FOUND` | 404 | 班级 ID 不存在 | `ClassNotFoundException` |
| `CLASS_HAS_STUDENTS` | 409 | 班级下仍有学生时被删除 | `ClassHasStudentsException` |
| `CLASS_NAME_DUPLICATED` | 409 | 同专业下班级名重复 | `ClassNameDuplicatedException` |
| `MAJOR_CODE_DUPLICATED` | 409 | 专业代码重复 | `MajorCodeDuplicatedException` |
| `MAJOR_HAS_ACTIVE_CLASS` | 409 | 专业下有未停用班级时被停用 | `MajorHasActiveClassException` |
| `PARAM_INVALID` | 400 | Bean Validation 失败或分页参数越界 | `ParamInvalidException` |
| `SYSTEM_ERROR` | 500 | 未捕获异常 | 由全局处理器兜底，不单独建子类 |

约定：

- `STUDENT_NOT_FOUND` 这类名称中的 `STUDENT` 与 P01 的表 `p01_student`、模块段 `STU` 指向同一领域，
  但三者的书写形式不同（表名 snake_case、编号缩写、错误码领域段全称），**不要互相替换**。
